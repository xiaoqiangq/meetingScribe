# 实时转写

实时入口独立于上传音频、视频和普通麦克风录音。原文识别使用现有
Qwen3-ASR-1.7B 权重，通过独立 vLLM 环境调用官方流式 API；说话人使用
现有 Nemotron-3-Diarization；FSMN VAD 和 ForcedAligner 使用原有 Qwen 环境。
没有新增 ASR 模型权重，不提供翻译。

## 页面与麦克风

「添加音频 → 实时转写」打开独立的 `/live` 页面。开始前可选择输入设备；
系统默认选项遵循浏览器与操作系统的默认麦克风。获得权限后显示设备名称，
录音时显示实际使用的设备与输入音量。设备列表随设备插拔更新。

开始录制时自动创建普通音频项目，实时控制区嵌入现有项目详情页。标题、
角色修改、文字视图、字词时间戳、选中文字添加笔记、字幕/文字下载，均复用
上传音频项目的组件和处理流程。已确认文字进入同一套繁简转换与段落展示；
未确认文字浅色显示，不能将其当作最终结果。说话人编号只属于当前会话。

页面显示已采集、GPU 已处理、服务器已保存的音频时长，以及待处理块数、
确认说话人数。每块音频在调用模型前写入并同步到服务器 WAV 文件，模型响应
后保存文字检查点。重试上一块不会重复追加音频。配额与项目归属沿用账号规则。
原始浏览器录音仍可在结束后单独下载；项目回放使用 16 kHz 单声道 PCM WAV。

暂停时可使用现有播放器的进度条、跳转、字词定位与回放；继续录制时暂停
播放器，避免将回放再次录入。结束后可使用原有会议纪要和聊天入口。
刷新或关闭仍会提示确认：已经被服务器保存的音频和文字保留，尚未发送或
尚未确认的内容不能保证保存。中断的项目标记失败并保留已存结果，不自动
重跑离线转写；需要时可通过原有项目流程重新处理。音量为零时应检查输入设备。

## 数据流

浏览器 AudioWorklet 将麦克风输入转成 16 kHz 单声道 PCM16，约每秒发送一块。
请求使用现有登录凭据，通过 Go API 转发至 GPU 上的回环地址。分块带连续序号，
重复的上一块可重试，乱序或缺块会被拒绝。临时文字持续修订，确认文字由
ForcedAligner 补字词时间，再按 Nemotron 连续时间线分配说话人。

增量 Chunk Manager 直接引用现有上传规划器的 10/20/30 秒时长参数与 1.5 秒
长停顿阈值，不修改离线规划器。短停顿后续说时保留 Qwen 状态；较长片段在
长停顿或目标时长附近的 VAD 端点确认。不足十秒的短发言等待至少三秒明确
静音后确认；连续讲话最多三十秒。稳定人物变化等待约 0.8 秒额外输入，实际
切点为确认时接收到的音频边界，不回溯重喂已识别音频，也不等同于离线规划
能选择的精确切换中点。切点和原因记录在 metadata.chunk_cuts 中。

说话人时间线要求足够的累计置信活动才发布新编号，并要求连续稳定的帧段；
重叠或低置信度保留待确认，不直接沿用上一人。已知人物至少约 0.24 秒且
置信度较高的短插话可保留人物标签，但不强制切块。阈值是保守策略，不能保证
每次短插话或相似声音都能正确区分。结束时仍使用完整缓存复核字词标签。

确认文字的段落合并与音频切点分开。字级结果和无字级回退片段走同一条
展示合并逻辑，保留字词索引与时间戳；临时文字接在当前发言段末，换人时另起
一段，并且不参与已确认文字的笔记选区。暂停停止浏览器采样并保留会话；恢复
继续同一音频时间线，暂停时长不写入录音。结束时冲刷尾部音频和最后一句。

录音与文字持续自动入库，不自动启动离线转写。结束页的「按上传流程重新
转写」复用原有配置选择与任务接口，使用完整已保存 WAV，并更新此项目的
转写结果；需要用户手动选择配置并开始。网络中断或积压时保留服务器已保存
的音频和文字，以及浏览器录音下载入口。旧客户端的手动保存接口仍兼容。

## 独立运行环境

`runtime/requirements-realtime.txt` 仅用于新虚拟环境，禁止安装到既有上传环境。
Qwen 的 vLLM 版本按官方 `qwen-asr==0.0.6` 固定为 `vllm==0.14.0`。
NeMo 与 ForcedAligner 各运行一个持续子进程，分别使用其原有解释器，避免
PyTorch、Transformers 和 NeMo 依赖互相覆盖。

配置示例见 [realtime.env.example](../deploy/realtime.env.example)。服务通过
`python runtime/realtime/service.py` 启动，只监听 `127.0.0.1`。Go 服务需要
`MEETINGSCRIBE_REALTIME_URL`；未配置或模型未就绪时入口提示尚未就绪。
浏览器麦克风需要 HTTPS 或 localhost 安全上下文。

首版限制一个实时会话、单次最长 30 分钟。普通任务已经排队或运行时，实时
会话返回忙碌；实时会话期间普通转写提交须稍后重试。上传和浏览已有结果仍可用。
共享任务准入锁和可续期租约防止两条转写路径同时抢 GPU；断开后租约自动过期。
vLLM 的 GPU 预算为总显存的 15%，此外须预留说话人模型、对齐器与现有服务的
实际占用。上线前必须实测延迟、显存和不同说话人的效果，不能将缓冲时长当作
端到端延迟承诺。

## 定向验证

- `python3 -m unittest discover -s runtime/realtime -p 'test_*.py'`
- `python3 -m unittest discover -s runtime/funasr -p test_chunk_manager.py`
- 前端 `npm test` 与 `npm run type-check`
- Go `go test ./internal/api -run '^TestRealtime'`
- Go `go test ./internal/queue -run TestRealtimeAdmissionLease`

测试不递归清理目录。正式前端构建使用新目录，保留 `emptyOutDir: false`。
GPU 验证录音和日志保留在私人验证目录，不纳入版本库。
