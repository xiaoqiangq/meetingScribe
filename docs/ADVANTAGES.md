# 会记P的优势与适用边界

[English](ADVANTAGES.en.md) · [返回首页](../README.zh-CN.md) · [完整流程](ARCHITECTURE.md)

会记P把语音转文字、说话人时间区间、逐字试听和会议纪要接成可复核的会议工作流。尤其适合中文长会议、分议题讨论、发言阵容变化，以及需要人工确认人物身份的场景。

## 优势一：适合中文会议的模型组合

Qwen3-ASR-1.7B负责转写，Nemotron-3-Diarization负责说话人时间区间，Qwen3-ForcedAligner-0.6B把文字对齐到音频，FSMN-VAD提供有声与静音位置。各组件的输出用于切片、字词定位及人物归属，用户可沿时间轴试听复核。

Qwen官方说明支持30种语言及22种中文方言/口音，包含中文、英文、粤语、吴语、闽南语等。**当前网站的Qwen桥接固定为中文配置**，纯英文、多语言切换和各方言尚未逐项验收；模型支持的范围不等于网站已验证的范围。[Qwen模型说明](https://huggingface.co/Qwen/Qwen3-ASR-1.7B)

Nemotron单次运行最多支持8个说话人通道，也能输出重叠发言区间。它提供匿名标签，不直接给出姓名；8个通道是容量上限，实际区分效果仍受收音、重叠、发言长度和音色变化影响。[NVIDIA模型说明](https://huggingface.co/nvidia/Nemotron-3-Diarization)

## 优势二：结合语音结构切片，保留上下文

Chunk Manager是规则切片组件。它结合VAD和Nemotron区间，一般生成10–30秒核心块，优先选择静音、稳定的说话人切换位置，必要时寻找低能量切点；尾块可以更短。

| 设计 | 对用户的价值 |
| --- | --- |
| 结合静音和人物区间选择边界 | 尽量减少在连续发言中间切断的机会 |
| 保留块内静音，添加前后padding | 保留停顿与邻近语境，帮助识别和时间对齐 |
| ASR与ForcedAligner读取同一块音频 | 让文字与时间定位使用一致的输入 |
| 按字词时间中点归属核心块 | 去除padding产生的重复输出，保留真实重复发言 |
| 控制单次输入长度 | 控制每次推理的输入规模，便于定位局部错误 |

这些设计服务于转写连续性和结果复核，尚无独立对照试验证明固定幅度的准确率或显存改善。Chunk Manager本身不识别人、不识别话题。

## 优势三：按topic管理长会议和变化的发言阵容

用户手动设置分界，各topic串行运行Nemotron，使用独立缓存和人物标签。先在各段内区分人物，再推荐跨topic联系，用户试听确认后统一身份。

```text
长会议 → 手动topic分界 → 各topic独立分人
                           ↓
              保留topic1/speaker_0等本地标签
                           ↓
              推荐跨topic联系 → 试听并确认
                           ↓
                    统一人物与姓名
```

这一策略缩小每次人物追踪的范围，适应不同议题由不同人员发言的会议；独立缓存避免上一topic的历史状态直接延续到下一topic，也便于按议题复核和保存分段结果。它旨在缓解长时间追踪中的人物漂移，改善幅度仍需项目样本评测。

**整场会议可以包含超过8位不同人物，前提是各topic内的不同说话人数仍在单次模型容量内。**例如topic1为A–E，topic2为D–I；确认D、E的跨段联系后，全场可统一为9人。同一topic有超过8人轮流讲话时，即使没有同时说话，也不能靠这套分段策略保证全部区分。

topic不是自动检测；两个topic的speaker_0不能直接视为同一人。分界附近可能出现误差，后续Chunk Manager仍按完整音频规划，不强制在每个topic边界切块。详见[时间轴与topic规则](ARCHITECTURE.md)。

## 优势四：原生特征推荐与人工确认结合

分人完成后，从各人物的清晰原始音频片段提取同一Nemotron checkpoint的原生特征，推荐声纹库姓名及跨topic人物联系。标准流程不使用TitaNet，也不把登记声纹预注入Nemotron的分人缓存。

原始标签和时间区间得以保留，用户通过试听确认姓名与联系。推荐是辅助判断；特征相似度不是身份概率，这套特征推荐也不是官方声纹验证模型。这样可以在保留分人结果的基础上逐步完成身份核对。

## 优势五：从试听复核到可追溯纪要

字词高亮、Listen跳转、人物改名和导出支持逐段核查。会议纪要提供可选模板、带来源版、清洁版与历史版本，便于回听依据、分享及比较不同模板的生成结果。

转写、分人和原生特征推荐在本地运行；纪要使用管理员配置的本地或外部LLM。外部LLM会收到提交的文字和人物信息，需要全程本地处理时应配置本地LLM。

## 性能与验证范围

官方模型基准、项目构建验证、真实会议效果属于不同证据。Nemotron官方AliMeeting近场/远场DER在30.4秒延迟配置下分别为6.40%/10.47%；该数据集为2–4人，不能据此承诺8人会议效果，也不是会记P的端到端实测。延迟参数不是整段会议的处理耗时。[官方评测](https://huggingface.co/nvidia/Nemotron-3-Diarization)

项目已在A100部署环境运行中文链路，GitHub CI通过应用检查和Docker构建；整站速度、跨topic准确率及与商业产品的同条件比较尚未系统测量。独立全新GPU安装与业务验收仍待完成。详见[验证记录](VALIDATION.md)。

**我们的优势在于把成熟模型组合成适合中文长会议、可试听纠正、可确认身份、可保留纪要历史的工作流。**
